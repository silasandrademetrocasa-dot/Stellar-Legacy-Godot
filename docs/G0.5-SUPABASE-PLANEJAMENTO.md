# Plano do NOVO backend — Stellar Legacy Godot

Decisão: novo projeto Supabase separado, sem copiar IDs, tabelas ou registros históricos do projeto web. **Nenhuma alteração SQL executada na G0.5**.

- Separar ambiente desenvolvimento/homologação do Render e Supabase web atuais. Nunca usar chaves `service_role` no APK.
- Autenticação independente, com ID do jogador gerado pelo Auth novo; `display_name` controlado; identidade interna é um UUID novo, sem quaisquer IDs de referência de jogo antigo.
- Catálogo autoritativo projetado a partir dos NOMES reais do Stellar Legacy: `vrax`, `zyron`, `kharon`, `scavenger`, `colossar`, `dreadnox` etc. Chave legível (`slug`) e nome público (`display_name`). Nenhum nome antigo como `streuner`/`lordakia`/`mordon` deve existir no esquema novo.
- Esquemas de dados futuros: perfis, sessões, naves, configurações, inventário, missões, clãs, progressão, portal/rotas e auditoria de combate. RLS por jogador/clã e servidor autoritativo para economia e dano.
- Backend autoritativo no Render para multiplayer, snapshots, interpolation, delta updates, NPC e farm; preservar conexão somente para estado em tempo real, assets locais no Android.
- Começar pela especificação do protocolo e testes de segurança antes de criar tabelas ou conectar usuários.
